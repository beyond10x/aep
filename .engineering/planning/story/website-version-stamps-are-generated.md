# Story: The website's version claims are generated from the tag

## Outcome

A visitor to the front page is told which version this is, and it is right. When this was filed
`website/src/pages/index.tsx` showed a chip reading `0.7.1-infra-waves-1-4` — twenty-six tags behind
what was live — and that is the first version number any visitor ever sees.

## Context

The site makes claims about the repository that the repository can answer, and each was typed by
hand, so each had drifted by a different amount. Measured 2026-08-30, at 0.33.0:

| where | said | behind |
|---|---|---|
| `website/src/pages/index.tsx` release chip | `0.7.1-infra-waves-1-4` | 26 tags |
| `website/docs/status/where-this-stands.md` currency line | as of the tag `0.32.1` | 1 tag |
| `website/docs/status/where-this-stands.md` gate line | `task check` runs **twenty steps** | correct on the day, wrong the next time a step lands |

**One candidate was examined and rejected.** `website/docs/status/limitations.md:34` reads *"Two
durable backends implement the contract, as of `0.27.0`"*. That is not a stale stamp — it is a
historical fact about **when** something became true, and rewriting it to the newest tag would make
it say something false. It stays hand-written. The distinction is the whole point: a generator that
cannot tell a currency claim from a *since* claim would have corrupted this line on its first run.

The repository already solved this once, in the same words: `docs/status.md`'s delivered-waves table
is generated by `cargo xtask status` from the annotated tags, and `status-check` fails when it
drifts. Nothing in that mechanism is specific to `docs/status.md` — it is a marked region, a
generator and a `--check`.

The gate-step line joined the story after the fact, and belongs to it: it is the same class of
claim, it went wrong the moment `docs-check` landed
(`story:cli-reference-covers-every-verb`), and it is derivable from `Taskfile.yml`'s own `check:`
block. A stamp mechanism that leaves the neighbouring sentence hand-written has not finished.

## Acceptance

- The three claims above sit in generated regions written by `cargo xtask status` — the tag and its
  date from the newest tag reachable from `HEAD`, the step list from `Taskfile.yml`.
- `cargo xtask status --check` fails when a region no longer matches, so `status-check` — already
  the second step of `task check` — covers the website.
- Nothing is added to the release procedure. `AGENTS.md` § *Releases* already runs
  `cargo xtask status` after the tag exists and commits what it wrote.
- A stamp edited by hand turns the gate red, proven by a test that edits one.
- `limitations.md`'s *since* claim is untouched.
