# Story: a lifecycle document declares which of its states are closed

## Outcome

Which statuses count as closed is read from each kind's lifecycle document. A lifecycle may carry
an optional `closed: [<state>…]` list; a terminal state (no successor) is always closed; a kind with
no lifecycle has no closed state. `aep plan artifact lifecycle <kind>` prints the closed set. Every
ladder under `artifacts/lifecycles/` that has an `implemented` or a `rejected` state declares it
closed.

## Context

`architecture-design:store-pack`, item 4 of *The packed representation*. Today the only structural
notion is `ArtifactLifecycle::is_terminal` (`crates/govern/aep-domain/src/artifact.rs`), which makes
only `archived` closed for a story; the operator's request counts `implemented`, `archived` and
`rejected` as closed. `review-result` (`active -> archived`) must stay closed at `archived` only,
which no structural rule over the ladder can tell apart from story's `implemented -> archived`, so
the document has to say it.

## Acceptance

A kind's closed set is exactly the states its lifecycle document lists under `closed:` plus its
terminal states, everywhere the tooling reads, prints, validates or publishes it. Checked by:

- a CLI test asserting the printed closed line for `story` (`implemented`, `rejected`, `archived`),
  `review-result` (`archived`) and `approval-record` (none);
- a test over every file in `artifacts/lifecycles/` asserting that each ladder with an `implemented`
  or `rejected` state lists it in `closed:`;
- a test that a lifecycle document whose `closed:` names a state its `transitions` do not declare is
  refused when the protocol tree loads, with a stable code naming the kind and the state;
- a domain test that a lifecycle without `closed:` loads as before and its closed set is its terminal
  states;
- `schemas/generated/artifact-lifecycle.schema.json` regenerated by `cargo xtask schema` and holding a
  `closed` property (absent before this story).
