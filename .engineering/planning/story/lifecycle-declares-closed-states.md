# Story: a lifecycle document declares which of its states are closed

## Outcome

Which statuses count as closed is read from each kind's lifecycle document. A lifecycle may carry
an optional `closed: [<state>…]` list; a terminal state (no successor) is always closed; a kind with
no lifecycle has no closed state. `aep plan artifact lifecycle <kind>` prints the closed set. The
protocol tree's ladders that have `implemented` or `rejected` declare them closed.

## Context

`architecture-design:store-pack`, item 4 of *The packed representation*. Today the only structural
notion is `ArtifactLifecycle::is_terminal` (`crates/govern/aep-domain/src/artifact.rs`), which makes
only `archived` closed for a story; the operator's request counts `implemented`, `archived` and
`rejected` as closed. `review-result` (`active -> archived`) must stay closed at `archived` only,
which no structural rule over the ladder can tell apart from story's `implemented -> archived`, so
the document has to say it.

## Acceptance

1. `aep plan artifact lifecycle story` in this repository prints a line naming the closed states
   `implemented`, `rejected` and `archived`; for `review-result` only `archived`; for
   `approval-record` none. Checked by a CLI test asserting the printed line.
2. A lifecycle document whose `closed:` names a state its `transitions` do not declare is refused
   when the protocol tree loads, with a stable code naming the kind and the state. Checked by a test
   asserting the code.
3. A lifecycle document without `closed:` loads as before, and its closed set is its terminal
   states. Checked by a domain test.
4. `schemas/generated/artifact-lifecycle.schema.json` is regenerated by `cargo xtask schema` and
   `schema-check` passes.
